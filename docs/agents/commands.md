# Commands

This module of `AGENTS.md` lists the commands of the repository and the checks of CI.

Node 24 or later, and pnpm from the `packageManager` field of `package.json`.

| Command | Action |
|---|---|
| `pnpm install` | Installs the dependencies. |
| `pnpm dev` | Writes the SF3 preset files into `public/sf/`, the changed demo files into `public/demos/` (design 8.3), and `perf/perf-60.mid` (design 9.5), then starts the Vite dev server. The audio spike is at `/spike.html`, the model gallery at `/gallery.html`, and the animal views at `/views.html` (design 7.1). `/#demo=<id>` shows another demo, and `/#demo=perf-60` shows `perf-60.mid`. |
| `pnpm build` | Writes the SF3 preset files and the demo files, then builds the site into `dist/`, with the third-party license file (design 7.3). `pnpm vite preview` serves `dist/`. With `ZOOPHONY_BASE=/zoophony/`, the build and `vite preview` use the base path of GitHub Pages (design 9.2). |
| `pnpm size [--base <ref>]` | Prints the gzip size of the first download, and fails above 1 MB (design 7.2). Run it after `pnpm build`. With `--base <ref>`, it also extracts the commit, a branch, or a tag into a temporary folder, runs `pnpm build` of the commit there, and prints the total of the commit, the total of the working tree, and the difference. It removes the folder at the end, also after a failure and after Ctrl-C. The build of the commit takes about 3 s. |
| `pnpm screenshots <dir> [--sheet] [--play] [--ui] [--drawer] [--load] [--shots]` | Builds the site, serves `dist/` with `vite preview`, and writes the review screenshots of design 9.8 into `<dir>` as WebP files of at most 300 kB: each demo at 1440 × 900, the default demo at 390 × 844, the two gallery pages, the animal views, and the five model sheet pages (design 7.1). `--sheet` adds `species-sheet.webp`, a close view of each gallery model. `--play` adds the default demo and the Beethoven 9 demo at 1440 × 900, and the default demo at 390 × 844, after 6 s of play. `--ui` adds the first screen and the open drawer during play, `--drawer` adds the seat list, the settings, the credits, and the drop overlay, and `--load` adds the first screen during the load, the load failure, and the full-page message with no WebGL2, at both sizes of the prototype screenshots. `--shots` adds a frame of each kind of camera shot of each demo at both sizes (design 9.8). It uses headless Chromium with ANGLE on Metal (`pnpm exec playwright install chromium` one time), and it stops the server at the end. |
| `pnpm snapshot` | Builds the site and saves screenshots of the current state into `docs/snapshots/<commit date>-<short hash>/`: the default demo during play at 1440 × 900, with the drawer closed, in the default view of "Reset view", 3.5 s after a seek to 30 s, and a close view of each gallery model. It writes a `README.md` with the commit, and a note when the working tree has changes. The folder and the file names depend only on the commit, so a second run on the same commit writes the same files again. The play frame can differ by a few milliseconds of song time and of the idle motion. It uses the browser of `pnpm screenshots`, and it stops the server and the browser at the end. |
| `pnpm sheet-check <sheet> <dir>` | Builds the site and compares a model sheet page of `views.html` with its sheet in `docs/reference/` (design 7.1). It writes into `<dir>` the page at the size of the sheet, the silhouette of the body (`?sheet=<id>&matte`), and the sheet above the page. With a matte in `tools/sheet-mattes/<id>.png`, it also prints the silhouette IoU of each view, the top and the bottom rows, the five rows with the most different pixels on each side of the seat, and the color medians and the value percentiles of the sheet and of the page. It writes the difference image and `<id>-rows.txt`, the runs of each second row of the sheet and of the page. `tools/sheet-mattes/make_matte.py <id>.json` makes each matte from the config of its sheet: the foreground rule, the props to ignore, and the rows of the labels. It stops the server and the browser at the end. |
| `pnpm pose-probe <sheet> [--time <s>]... [--set <changes>]...` | Prints the posed elbow, wrist, and palm of each arm of the sheet pose of a model sheet (design 7.1), in head heights from each shoulder joint (out, up, forward), and the direction of the tip of the instrument. `--time` takes the song time of the pose in place of the time of the sheet. `--set` changes values of a hold in memory, as `pnpm pose-depth` does, and prints each variant after the base. It runs in about 1 s with no build, so a tuning round is: change a hold with `--set`, run the probe, and repeat. Then write the value into the source file. |
| `pnpm pose-depth <role> [--demo <id>]... [--soloist <species>] [--set <changes>]... [--bones <list>] [--into <list>] [--times <list>] [--gaps] [--base <ref>] [--json <file>]` | Runs the sweep of a role (`conductor`, `pianist`, `violinist`, `violist`, `cellist`, or `flutist`) over each demo with the role (design 9.3). The violinist sweep takes the first seated rabbit and the first seated red fox of each demo, and each standing soloist of the two species, and its note targets put the bow hair on the strings. The violist sweep takes the first seated cat of each demo with violas, and each standing cat soloist. The cellist sweep takes the first seated dog of each demo with cellos, and a cellist does not stand. The flutist sweep takes the first seated tan fox of each demo with flutes, and each standing tan fox soloist, and its note targets put each palm on its grip at the start of each phrase. Each player gets its own sample sets. It poses the skin of the GPU, and prints the deepest point of each moving part in each obstacle of the role, with its time, its bone, its place along the bone, and its limit, and the largest note-target error of each hand. `--set` changes values of a hold in memory, such as `piano.lean=16deg` or `piano.restL.lap.offset=-0.75,0.1,0`. The root `<instrument>@<species>` changes the own hold of a species (`SPECIES_HOLDS` of `pose/bowed-rig.ts`, `SPECIES_WIND_HOLDS` of `pose/winds.ts`), such as `violin@rabbit.lean=12deg` or `flute@fox-tan.lipShift=0,-0.05,0`. The root of the instrument (`violin`) does not change it. Two holds can share an object or a list through a spread, such as `violin.restBow` and `viola.restBow`, or the bow tip of the rest of the rabbit and the red fox. A change with the root of an instrument changes the shared object, and the text of the variant names the other paths that the change moves too. A change with the root `<instrument>@<species>` first copies each object and list of its path in memory, so that it changes only that species (`copyPath()` of `tools/hold-sets.ts`). It stops on an unknown key. A value that is `null`, an object, or a list that is not a list of numbers takes JSON text with the keys and the kinds of the old value, such as `viola@cat.restBow.via={"tip":[-0.3,0.3,-1],"hair":[0,-1,0],"reach":[0,0,-0.4]}`, and a number in it can have the unit `deg`. A field that is `null` takes the keys of its entry in `NULL_FIELDS` of `tools/hold-sets.ts` (`BowVia`, the rest of a bowed hold, `standBow`, and `restFreeL`), and a field of that table also takes `null`. A key that the old value does not have stops the run, and so does a missing key. A path below a field that is `null` stops the run with a message that names the field and its keys. Each `--set` is one variant, with its changes separated by `;`, and the run prints one table with one row for each variant. `--bones` measures one part for each bone, with the limits of the part of the role that holds the bone. `--into` selects the obstacles. `--times` takes song times of a play in place of the sample sets, with the wall times and the limits of a play. `--gaps` also prints the smallest gap in each sample set from the head to each obstacle except the body, such as the case of the piano. It also prints the smallest gap from each paw to the body. Each gap has its time and its bone. A gap is the distance of the nearest points of the posed skin and the closed obstacle, and 0 when they touch (`surfaceGap()` of `pose/test-clearance.ts`). The table gives the smallest gap over the demos. With `--bones forearmL,forearmR,handL,handR --into body`, one variant of the pianist over both demos takes about 6 s, and all parts take about 18 s, or 37 s with `--gaps`. One time takes less than 1 s. The label of each player names its species, such as `violinist 4 (fox-red, chair)`. No demo has a standing violin soloist. `--soloist <species>` sweeps the species as the standing soloist of the violin and piano duo of the chamber test files in place of the demos (`soloistScene()` of `pose/test-sweep-roles.ts`): the species takes the place of the violinist with the instrument of the role. The `violinist` takes `rabbit` or `fox-red`, and the `violist` takes `cat`. The bow then takes a point at each 1 cm along each edge in place of its corners (`bowSweep()` of `tools/bow-sweep.ts`). The rows give the depth of the bow in each obstacle and in the upper arms and the forearms (`arms`), and the lowest point of the bow above the floor as the gap `bow~floor`. The label of the player starts with `violin-piano`, such as `violin-piano violist 0 (cat, stand)`. The option does not go with `--demo`. On 2026-10-16, one species took 8 s to 10 s, and its rest gave the values of `docs/research/2026-10-16-cat-seat/stand-bow.txt`. `--json <file>` writes the rows of each variant as JSON. `--base <ref>` sweeps a commit, a branch, or a tag and the working tree at the same time, each in a child process (`probeBeside()` of `tools/ref-tree.ts`). The commit runs the base with no change, and the working tree runs each variant. A role that the commit does not have stops the run before the probes with the message "The ref <ref> has no role <role>". After the output of the working tree, the tool prints one compare for each variant. It has one row for each species, sample set, and pair, with the deepest point of both trees in cm and in the H of each body. A mark `GROWS` follows a depth whose value in H grows by more than one step of the print (0.1 cm). The JSON of each side holds the format version of its tool and the field `since`: the oldest version that its version only adds fields to (`ProbeFormat` of `tools/ref-tree.ts`, `ROWS_SINCE`). Two versions compare when the newer version only adds fields to the older version. Then the tool prints a note. When the working tree is newer, the compare gives `-` for each new field on the side of the commit. When the commit is newer, the compare shows the fields of the version of the working tree. Else the compare stops with both versions in the message (`formatNote()`): each side runs its own tool, so a changed field gives false differences. The JSON of the commit goes into a cache by tree, `probe-cache/` in the common folder of git, which each worktree shares (`baseCacheFile()` of `tools/ref-tree.ts`). Its key holds the trees of `PROBE_PATHS` of the commit, the scripts of the working tree that the probe copies, the arguments of the commit, Node, and the lockfile. A second run with the same key prints `base: cached`, and runs only the working tree. `PROBE_NO_CACHE=1` runs the commit again. On 2026-10-16, `pnpm pose-depth violist --demo bach-bwv1050 --base main` took 13.5 s with 27.9 s of CPU, and 13.0 s with 13.8 s of CPU and `base: cached`, because the two sides run at the same time. A commit whose tool does not know an option of the run, such as `--soloist` before 2026-10-16, stops the run with the message of its tool. The folder goes away at the end, also after a failure and after Ctrl-C. With `--base main`, the violinist took 304 s over 14 demos at a load average of 27, and 16 s over one demo. The source files do not change. |

| `pnpm body-probe [--out <file>] [--no-poses]` or `pnpm body-probe --base <ref>` | Probes the rest joints and a hash of the body mesh of each species on each support and standing, and the skeleton and a mesh hash of each player of the section cast and of the conductor. The mesh hash covers the places, the colors, the bones, the blend weights, and the finishes, and for a studio body the corrective shapes and the smooth normals. Each of these fields also has a hash of its own. It also gives a hash of the poses of each player and of the conductor of each demo in four sample sets. Each set has a hash of all its poses and a short hash of each sample, from the rotations, the offsets, and the blink in micro-units. `--out <file>` writes the probe as JSON of about 2.6 MB.
