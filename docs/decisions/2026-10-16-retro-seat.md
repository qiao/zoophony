# Decisions of the round retro-seat

The Section column names a section of the design. [`design.md`](../design.md) gives the file of
each section.

The retro of the round `cat-seat` of 2026-10-16 gave two slow steps. The docs took about 50
minutes, partly to find the design places that did not name the cat. The probe of the standing bow
took a script by hand, because no demo has a standing violin soloist. The manager asked for a docs
check of a species and for a standing soloist in `pnpm pose-depth`. The agent of the branch
`retro-seat` decided these rows.

| Decision | Section |
|---|---|
| `pnpm docs-species <species>` reads the three tables of section 8 of `docs/briefs/studio-body.md`, so the list of the docs of a new body, a new role, or a new hold stays one list for a person and for the tool. The cell "Heading" holds quoted anchors (the start of a heading, a bold line, a list item, or a paragraph) and code spans (the block that holds the code), with no line numbers, because the lines move with each round. The command replaces the grep for the places of the last species of the same route | 9.8 |
| The rows with no anchor got one: the notes of the skeleton are the item of `models/species.ts` under "Short legs." of 4.3, the text over the table of the shape parameters is the paragraph "The shape parameters of each species", and the sheet pages of 7.1 are the text of `VIEW_SHEETS`. The row of a decision file split into one row for each file | 9.8 |
| A column "Not for" names the species that a place is right not to name, and the column "The place lists" gives the reason. The other choices were a mark at each place of the design, which puts the text of a tool into the design, and a rule in the tool for each reason, such as "a species with a sheet page", which needs code for each rule | 9.8 |
| The runs on the cat, the red fox, and the rabbit set these species in "Not for": the cat for the sheet pages of 7.1 (it has no sheet page in `VIEW_SHEETS`), the rabbit, the two foxes, and the cat for the docs of `lowpoly-studio/` (the studio builds none of their bodies), the tan fox for the bowed strings of 5.3, and the rabbit, the red fox, and the cat for the new row of the woodwinds of 5.3 | 9.8 |
| A place names a species when its text holds the id of the species, the id of its own body (`SpeciesParams.body`), or an English name of `DOC_NAMES` of `tools/docs-species.ts`, as a whole word with no regard to case. The two foxes share "fox" and "foxes", because the docs name their one mesh and rig `fox`, such as `?sheet=fox` and "fox, violins". The name of another species that holds a name of the species, such as "polar bear" for the bear or "tan fox" for the red fox, does not count | 9.8 |
| The scale of the instrument and the reach of each species in 4.6 are in the paragraph "The instruments follow the reference image", above "Sizes and holds". The table under "Sizes and holds" has one row for each instrument and names no species, so the rabbit, the red fox, and the cat each missed the old place of the two rows | 9.8 |
| A path with more than one file, such as `assets/models/<s>/README.md`, names a species when one of its files names it. The decision file of a hold can be any file of `docs/decisions/`, so its row only shows that a decision names the species | 9.8 |
| `pnpm pose-depth <role> --soloist <species>` builds the violin and piano duo of the chamber test files (`violinPianoDuoFile()`, `violin-piano.mid` of the shot tests) with the species in the place of the violinist, as `docs/research/2026-10-16-cat-seat/stand-bow.ts` did (`soloistScene()`). The place keeps the footprint of the rabbit, and a depth in the axes of the model does not change with the place. The role gives the instrument: the violin for the `violinist` and the viola for the `violist`. A species of another role stops the run, because the body obstacle of each role has the open loops of its own bodies | 9.3 |
| The soloist gets the sample sets of the role: the play, the lift, the rest at the wall time 10 s, and the lowering. `stand-bow.ts` took the rest at each 0.5 s from 10 s to 15.5 s. The rest of the sweep gave the values of `stand-bow.txt` within 0.1 cm: no depth of the bow in the body or in the arms, and the lowest point of the bow 12.9 cm (rabbit), 36.8 cm (red fox), and 39.7 cm (cat) above the floor | 9.3 |
| With `--soloist`, the part `bow` of the role takes a point at each 1 cm along each edge in place of its corners (`bowSweep()` of `tools/bow-sweep.ts`), and its columns keep the name `bow`. The sweeps of the demos keep the corners, so their values do not change: `pnpm pose-depth violist --demo mozart-k525 --base main` gave equal depths on both trees | 9.3 |
| The depth of the bow in the arms takes the upper arms and the forearms, as the rest columns of `pnpm hold-fit` do, because the paws hold the bow in a play. `stand-bow.ts` also took the paws, and gave 0.0 cm in the rest. The lowest point of the bow is a gap to the floor (`bow~floor`), so the table gives its smallest value | 9.3 |
| The run of the commit of `--base` gets `--soloist` too, so that both trees sweep the same scene. A commit with no such option stops the run with the message of its tool: `The option "--soloist" is not known.` | 9.3 |
