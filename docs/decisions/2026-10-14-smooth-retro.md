# Decisions of the retro of the smooth studio bodies

The Section column names a section of the design. [`design.md`](../design.md) gives the file of
each section.

On 2026-10-14, after the merge of the smooth studio bodies (`d46d7fbe`), the manager of the
session chose the items of the retro that are worth their cost (user rule of 2026-10-12). The
agent of the branch `retro-smooth` decided the rows below. The report
[`2026-10-14-rabbit-smooth-retro.md`](../research/2026-10-14-rabbit-smooth-retro.md) gives the
times and the measures. The user can reverse each decision. Then update the section that holds
it, and remove its row.

| Decision | Section |
|---|---|
| `--base <ref>` names a commit, a branch, or a tag to compare with the working tree in each tool: `pnpm body-probe`, `pnpm size`, and `pnpm close-views`. The option of `pnpm close-views` that names a running site is now `--url <url>`. `--base` keeps the meaning that `pnpm body-probe` gave it first, so one name has one meaning | 7.1, 9.8 |
| `tools/ref-tree.ts` holds the shared steps. `withRefTree()` extracts the tree of a commit into a temporary folder with `git archive`, and removes the folder at the end, also after a failure or a stop (INT or TERM). `withRefBuild()` extracts the whole tree, links the `node_modules` of the worktree, and runs `pnpm build` of the commit. The whole tree takes 0.8 s to extract, so a list of paths that a later build can outgrow is not necessary. `probeRef()` of the body probe keeps its list of paths, because it runs no build | 7.1, 7.2 |
| `pnpm size --base <ref>` prints the report of the working tree as before, then the total of the commit, the total of the working tree, and the difference. The limit of the working tree alone sets the exit code. The tool gives no difference of each part, because the names of the chunks hold content hashes. An unknown ref stops the tool before the measure | 7.2 |
| `pnpm close-views --base <ref>` renders the working tree first, then the commit, one after the other in one browser, so that two renders do not share the GPU. It writes each cell of the commit (`<role>-base-<moment>-<view>.png`), and the grid of the commit above the grid of the working tree as PNG and WebP. The label of each cell starts with the commit and its short hash, or with `working tree`, so each row has a label. The WebP keeps the limit of 300 kB of `toWebp()`, and the PNG is the copy with no loss | 7.1 |
| The mesh hash of `pnpm body-probe` covers each field of a mesh: the places, the colors, the bones, the blend weights, the finishes, and for a studio body the corrective shapes and the smooth normals of its render mesh (`studioRenderMesh()`). Each field also gets a hash of its own (`fields`), and the compare names the fields that changed, such as `mesh differs (colors, normals)`. A parametric body or a penguin has no normals field, because the scene calculates its crease normals from its places and its finishes (`shadeMesh()`), which the hash covers, with no setting of the body | 9.8 |
| A mesh with no studio skin keeps the mesh hash of the tool before, so a JSON file of that tool compares equal for the 80 parametric bodies. The 15 studio bodies and the 3 studio players get a new hash, and the compare says `no field hashes in the base`. The JSON grows by 30 kB, and its SHA-256 changes one time. `--base` runs one copy of the tool on both trees, so its compare stays exact. A field that only one probe has counts as changed, and a studio body of a commit before the smooth normals has no normals field | 9.8 |
| The players of the probe get the same hash of each field as the bodies, because a player with a studio body has the same corrective shapes and normals | 9.8 |
| `tools/break-test.sh` exits with 0 when a test fails, 1 when no test fails, 2 for a refused call or a run with no report, and 130 after Ctrl-C, so a script can read the result. It runs `pnpm exec vitest run` with no project, so a paused test file runs in the project `paused`. It prints the diff of the break, because a break that hits a comment changes nothing that a test reads. It refuses an untracked file or a file with changes before it sets the restore, so the restore never removes work. It runs only from the root of the worktree, where Vitest finds its config | 9.3 |
| `tools/break-test.ts` holds the pure part: the read of the JSON report of Vitest. A test file that does not load counts as a failure, because a break can stop an import. No test that ran gives the exit code 2. The test of the script runs it in a temporary repository with a fake `pnpm`, as the test of `tools/check-commits.sh` does | 9.3 |
| The rule of a changed setting goes into "Keep the docs true" of `AGENTS.md`. The rule of a break command for each rule of a TSDoc and the rule of the image probes with `uv` go into "Tests" | 9.6 |
| The range check of a measure goes into "Range and stop" of the implementation brief of `docs/briefs/studio-body.md`, beside the fallback rules. The implementation brief and the review brief also run the new compares and the break script | 9.8 |
| Design 7.1 and 7.2 get one sentence each on `--base <ref>`. These files are outside the file list of the brief, and the rule "Keep the docs true" asks for them | 7.1, 7.2 |
