# Decisions of the round retro-cat

The Section column names a section of the design. [`design.md`](../design.md) gives the file of
each section.

The retro of the cat round of 2026-10-16 gave its three slowest steps: the folds (about 45
minutes, with three probes by hand that read the corners of the folded faces), the fit of the
hold (about 30 minutes, with an edit of the code to try a via of the rest bow, because `--set`
could not write a field whose value is `null`), and the docs (about 40 minutes, partly to find the
places that name a species). The manager asked for a tool change for each step. The agent of the
branch `retro-cat` decided these rows.

| Decision | Section |
|---|---|
| The face table of `pnpm fold-probe --faces <n>` puts the corners of its faces into a second table under it in each run, with one row for each corner. The row of face 2118 of the violist had 292 characters with the weights of its corners alone, and the places and the moves of its three corners add about 270 characters. The weights of the corners move from the face table into that table, so that each corner row holds the facts of `docs/research/2026-10-16-cat-mesh/face-probe.ts`. The corners of faces 2007 and 2118 of the violist in the sample of that probe equal `face-probe.txt` | 4.4 |
| The corners are the corners of the worst fold of the face, the sample with the largest angle (`worstFold()`). A corrective shape gives two numbers for each corner: its move at its full weight in mm, and its weight in the sample. A third column gives the move of all shapes at their weights in the sample. The full move lets a reader compare a corner with the shapes of the rig config, and the weight shows the pose | 4.4 |
| The JSON text of `pnpm fold-probe --json` keeps the four fields of the worst fold with no corners (`foldOnly()`), so its format version stays 2. A new version would stop each `--base main` compare until the merge | 4.4 |
| The mark `ALL` of the face table goes to a face that folds in each sample of each sample set that has samples (`foldsInAll()`). A set with no samples, such as the play of a run of `pnpm hold-fit --sets lift,rest,lower`, does not count | 4.4 |
| The keys of a field that is `null` come from a table in `tools/hold-sets.ts` (`NULL_FIELDS`), by the path of the field below the hold, and each entry satisfies the type of its field, so a change of the type stops the typecheck. The other choice, the keys of a value of another hold at the same path, depends on the data: a field that is `null` in each hold would have no keys | 9.3 |
| `--set` also takes JSON text for a value that is an object or a list that is not a list of numbers, with the keys and the kinds of the old value. The brief named the via of the cat, and that via is an object since the cat round. A field of `NULL_FIELDS` also takes `null`, so a variant can turn off the via of a rest bow: `pnpm hold-fit violist --sets lift,rest,lower --set 'viola@cat.restBow.via=null'` gave 7.9 cm of the right forearm in the body while the arms lowered, against 7.4 cm of the direct mix in `2026-10-16-mesh-cat.md` | 9.3 |
| The text of a variant is the text of the command line, so it states the new value as the user wrote it, with a unit `deg` in its JSON. The old value and the new value of a change are JSON text when they are not a number or a list of numbers (`valueText()`) | 9.3 |
| The list of the docs of a new body, a new role, or a new hold is section 8 of `docs/briefs/studio-body.md`. It names the file and the heading of each place, with no line numbers, because the lines move with each round. It adds the grep that finds the places of the last species of the same route | 9.8 |
